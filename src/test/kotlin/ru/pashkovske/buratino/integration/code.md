# Интеграционные тесты

## Общие принципы

### e2e

Интеграционные тесты проверяют работу приложения в целом с mock-ами только внешних связей:

- Адаптеров. Если нужно сделать mock адаптера, [см. описание в кодовой базе (main)](../../../../../../main/kotlin/ru/pashkovske/buratino/code.md).
  Вспомогательные классы для mock-адаптеров можно найти в пакете [ru.pashkovske.buratino.mock](./mock)

Всё остальное проверяется по принципу end-to-end: делаются запросы в endpoint и проверяются их ответы. Иногда можно
проверить состояние реального bean-а

Если речь не считать адаптеров, стоит избегать таких механизмов как:

- `org.mockito.kotlin.whenever`; `org.mockito.Mockito.`when`` или им подобных
- `MockitoSpyBean`
- `org.mockito.Mockito.verify`; `org.mockito.Mockito.never` и им подобных

Вместо них следует пользоваться:

- `org.springframework.test.web.servlet` чтобы как сделать действие, та и проверить результат
- Запросы в базу данных
- `@Autowired` + методы production `@Bean`-ов, где остальные предыдущие способы не подходят

### Структура

Тесты организованы по модулям так же как и в кодовой базе, [см. main](../../../../../../main/kotlin/ru/pashkovske/buratino/code.md). Помимо этого
есть ещё 2 пакета:

- [ru.pashkovske.buratino.mock](./mock) - вспомогательные классы для mock-адаптеров
- [ru.pashkovske.buratino.configuration](./configuration) - тестовые Spring `@Configuration`

Остальные пакеты - это тесты на одноимённый модуль из кодовой базы. В пакетах есть `code.md` описывающий специфику
тестов конкретного пакета.
